# L'ÉCOLE SOLID AND CLEAN CODE
Apply principles pragmatically.

SRP: a module should have a coherent responsibility.
OCP: prefer extensions/configuration where appropriate.
LSP: substitutions must preserve expected behavior.
ISP: avoid forcing modules to depend on what they do not need.
DIP: high-level logic should not be unnecessarily coupled to low-level implementation details.

DRY: maintain one source of truth when responsibility is genuinely shared.
KISS: prefer the simplest design that satisfies requirements.
Cohesion: keep related responsibilities together.
Coupling: minimize unnecessary dependencies.

Do not apply SOLID mechanically when it creates unnecessary abstractions.
